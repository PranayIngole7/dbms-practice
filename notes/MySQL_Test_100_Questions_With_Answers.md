Q91. Explain the difference between DBMS and RDBMS.

- Definition of DBMS : Software used to store, manage, and retrieve dat1. It stores data as flat files or in a hierarchical/network model.
- Definition of RDBMS : An advanced database system based on Edgar F. Codd's relational model. It stores data explicitly in related rows and columns.
- Data storage : DBMS stores data as flat files or trees with no enforced logical links between different data sheets. RDBMS organizes data strictly into structures called tables (relations).
- Tables and relationships : DBMS handles data tables independently. RDBMS links tables dynamically using logical relationships (One-to-One, One-to-Many, Many-to-Many).
- Keys : DBMS lacks strict relational key constraints. RDBMS relies heavily on keys like Primary Keys and Foreign Keys to enforce database integrity.
- Examples : DBMS includes XML, FoxPro, and MS Access. RDBMS includes MySQL, PostgreSQL, Oracle, and SQL Server.
- One real-world example : An Excel spreadsheet storing a single list of customer phone numbers behaves like a DBMS. An e-commerce system linking a Customers table to an Orders table via customer IDs behaves like an RDBMS.
---

Q92. What is a key in a database? Explain:
	Keys are attributes or sets of attributes used to identify rows uniquely and establish links between tables.
	
- Primary Key : Uniquely identifies each record in a table. It cannot contain NULL or duplicate values.
- Foreign Key : A column in a child table that references a Primary Key in a parent table to maintain referential integrity.
- Candidate Key : A column or minimal set of columns that qualifies to be a primary key because all its records are unique and non-null.
- Alternate Key : Candidate keys that were not chosen as the Primary Key.
- Composite Key : A Primary Key that consists of two or more columns combined together to ensure uniqueness.
- Unique Key : Enforces uniqueness on a column so no duplicate values are allowe4. Unlike a primary key, it can accept one NULL value.

Q93. What is SQL? Explain the major categories of SQL commands. Give at least two commands/examples for each category.
- DDL (Data Definition Language): Defines, modifies, and manages the physical structure of database objects like tables. 
> Examples: CREATE, ALTER, DROP
- DML (Data Manipulation Language): Modifies, adds, and removes the actual data stored inside the tables. 
> Examples: INSERT, UPDATE, DELETE
- DQL (Data Query Language): Used exclusively to fetch and retrieve data from the database. 
> Examples: SELECT
- DCL (Data Control Language): Manages user access, permissions, and security rights for the database system. 
> Examples: GRANT, REVOKE
- TCL (Transaction Control Language): Manages transactions and changes made by DML statements to guarantee database consistency.
> Examples: COMMIT, ROLLBACK

### 1. What are Constraints in MySQL?
**Constraints** are rules or conditions applied to table columns in MySQL to restrict the type of data that can be inserted into or updated in a table. They ensure data accuracy, consistency, integrity, and reliability across the database system.

---

### 2. Explanation of Key Constraints

#### **PRIMARY KEY**
* **Definition:** A field or combination of fields that uniquely identifies each record/row in a table.
* **Key Characteristics:**
  * Must contain **unique** values.
  * Cannot contain `NULL` values.
  * A table can have **only one** Primary Key.
* **Example:**
  ```sql
  CREATE TABLE department (
      dept_id INT PRIMARY KEY,
      dept_name VARCHAR(50)
  );
  ```

#### **FOREIGN KEY**
* **Definition:** A column or set of columns in one table that references the `PRIMARY KEY` of another table. It establishes a link/relationship between two tables.
* **Key Characteristics:**
  * Enforces **referential integrity** (prevents orphan records).
  * Prevents inserting values that do not exist in the referenced parent table.
* **Example:**
  ```sql
  CREATE TABLE employee (
      emp_id INT PRIMARY KEY,
      emp_name VARCHAR(50),
      dept_id INT,
      FOREIGN KEY (dept_id) REFERENCES department(dept_id)
  );
  ```

#### **NOT NULL**
* **Definition:** Ensures that a column cannot store `NULL` (empty/missing) values.
* **Key Characteristics:** A value must always be provided for this column during insertion.
* **Example:**
  ```sql
  CREATE TABLE users (
      user_id INT PRIMARY KEY,
      username VARCHAR(50) NOT NULL
  );
  ```

#### **UNIQUE**
* **Definition:** Ensures all values in a specific column are distinct from one another.
* **Key Characteristics:**
  * Unlike `PRIMARY KEY`, a table can have multiple `UNIQUE` constraints.
  * Depending on MySQL configuration, `UNIQUE` columns can accept `NULL` values.
* **Example:**
  ```sql
  CREATE TABLE users (
      user_id INT PRIMARY KEY,
      email VARCHAR(100) UNIQUE
  );
  ```

#### **CHECK**
* **Definition:** Ensures that all values in a column satisfy a specific logical condition.
* **Key Characteristics:** Prevents invalid data entries that violate the condition.
* **Example:**
  ```sql
  CREATE TABLE account (
      acc_id INT PRIMARY KEY,
      balance DECIMAL(10,2),
      CHECK (balance >= 0)
  );
  ```

#### **DEFAULT**
* **Definition:** Provides a default predefined value for a column if no explicit value is specified during an `INSERT` statement.
* **Example:**
  ```sql
  CREATE TABLE orders (
      order_id INT PRIMARY KEY,
      status VARCHAR(20) DEFAULT 'Pending',
      order_date DATE DEFAULT (CURRENT_DATE)
  );
  ```

---

### 3. Importance of Constraints in Real-World Databases
1. **Data Integrity:** Constraints enforce strict data rules at the database level rather than relying solely on application software logi3.
2. **Prevention of Invalid Data:** Rules like `CHECK` and `NOT NULL` block corruption and incomplete data input at the source.
3. **Prevention of Duplication:** Constraints like `PRIMARY KEY` and `UNIQUE` eliminate redundant entries.
4. **Referential Consistency:** `FOREIGN KEY` constraints preserve relations across relational tables and prevent orphan records during deletions or updates.
5. **Business Logic Enforcement:** Constraints enforce business boundaries directly within the schema design (e.g., age restrictions, non-negative account balances).

### SQL Operators with Examples

#### 1. Arithmetic Operators
Used to perform mathematical operations on numerical dat1.

* `+` (Addition)
* `-` (Subtraction)
* `*` (Multiplication)
* `/` (Division)
* `%` or `MOD` (Modulus / Remainder)

**Examples:**
```sql
-- Calculate bonus as 10% of salary
SELECT emp_name, salary, (salary * 0.10) AS bonus FROM employee;

-- Calculate daily wage (assuming 30 working days)
SELECT emp_name, (salary / 30) AS daily_wage FROM employee;
```

---

#### 2. Comparison Operators
Used to compare two values, returning a Boolean truth value (`TRUE`, `FALSE`, or `NULL`).

* `=` (Equal to)
* `!=` or `<>` (Not equal to)
* `>` (Greater than)
* `<` (Less than)
* `>=` (Greater than or equal to)
* `<=` (Less than or equal to)

**Examples:**
```sql
-- Find employees earning exactly 60,000
SELECT * FROM employee WHERE salary = 60000;

-- Find employees with salary greater than or equal to 45,000
SELECT * FROM employee WHERE salary >= 45000;
```

---

#### 3. Logical Operators
Used to combine multiple condition predicates in a SQL clause.

* `AND` (Returns TRUE if all combined conditions are TRUE)
* `OR` (Returns TRUE if at least one condition is TRUE)
* `NOT` (Inverts the logical evaluation of a condition)

**Examples:**
```sql
-- AND: Find employees in IT department earning over 50,000
SELECT * FROM employee WHERE department = 'IT' AND salary > 50000;

-- OR: Find employees in IT or HR departments
SELECT * FROM employee WHERE department = 'IT' OR department = 'HR';

-- NOT: Find employees NOT in Sales department
SELECT * FROM employee WHERE NOT department = 'Sales';
```

---

#### 4. BETWEEN Operator
Filters range matches (inclusive of boundaries).

**Syntax:** `expression BETWEEN low_value AND high_value`

**Example:**
```sql
-- Find employees with salary between 30,000 and 60,000 (inclusive)
SELECT * FROM employee WHERE salary BETWEEN 30000 AND 60000;
```

---

#### 5. IN Operator
Checks whether a given column value matches any value in a defined list.

**Syntax:** `expression IN (value1, value2, ...)`

**Example:**
```sql
-- Find employees located in Pune, Mumbai, or Bangalore
SELECT * FROM employee WHERE city IN ('Pune', 'Mumbai', 'Bangalore');
```

---

#### 6. LIKE Operator
Used for pattern matching with text wildcard strings.

* `%` represents zero, one, or multiple characters.
* `_` represents a single character.

**Examples:**
```sql
-- Name starts with 'A'
SELECT * FROM employee WHERE emp_name LIKE 'A%';

-- Name ends with 'n'
SELECT * FROM employee WHERE emp_name LIKE '%n';

-- Second letter of name is 'o'
SELECT * FROM employee WHERE emp_name LIKE '_o%';
```

    student_id INT NOT NULL,                           -- NOT NULL
    course_code VARCHAR(20) NOT NULL,                  -- NOT NULL
    semester INT NOT NULL,                             -- NOT NULL
    academic_year INT DEFAULT 2026,                    -- DEFAULT
    status VARCHAR(20) DEFAULT 'Enrolled',             -- DEFAULT
    FOREIGN KEY (student_id) REFERENCES student(student_id) -- FOREIGN KEY
);
